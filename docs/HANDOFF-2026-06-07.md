## Key decisions & rationale (read before touching fonts/UI)

- **Pixel font is intentional — do NOT swap typefaces.** Mid-session I wrongly converted the
  Cutoff/Res/FX/Filter-Env pixel labels (Press Start 2P) to Lato Bold to fix "too weak/small";
  the user objected ("why did you change the font? I didn't ask for that"). It was reverted.
  Rule learned: "labels too weak / too small" → make them **bigger/bolder in the same typeface**,
  not a different font. Press Start 2P is the deliberate C64 look for slider labels + headers.
- **`gm::ui` (the shared `ghostmoon-oss` library) was deliberately NOT modified.** It's shared with
  Nessy/Pedalboard3. Hover and the C64 keyboard are implemented **Breadbin-local** (in
  `BreadbinLookAndFeel` / the `C64Keyboard` subclass) on purpose. Keep new UI tweaks local unless a
  change genuinely belongs in the shared lib.
- **Checkbox "weakness" was color + size, not weight.** Toggle text was already bold 10px; the
  fix was off-state color (`txt2`→full `txt`) + size (10→12px). The dot indicator carries on/off
  state, so the text no longer dims when off.
- **Hover is buttons/toggles only by design.** Knobs need a repaint-on-hover hook because JUCE
  `Slider` doesn't repaint on mouse enter/exit — that's why it was scoped out (see Next steps #2).
- **Phase D motion defaults (from the spec):** blinking cursor ON, scope scanline drift ON,
  animated mod rings **OFF** (opt-in, persisted in APVTS state tree), PETSCII out of scope.

## How to build / test / run

```bash
# Clean rebuild (REQUIRED — see gotcha below)
cmake --build build --config Release --target Breadbin_All --clean-first

# Tests
cmake --build build --config Release --target BreadbinLFOTests --target BreadbinIntegrationTests --target BreadbinMutationTests
ctest --test-dir build -C Release        # MutationTests shows "Failed" — see gotcha

# Launch standalone (kill any stale instance FIRST — see gotcha)
taskkill //IM Breadbin.exe //F ; sleep 1 ; start "" "build/Breadbin_artefacts/Release/Standalone/Breadbin.exe"
```

## Gotchas (these bit us this session)

- **Always `--clean-first`.** Incremental builds hit MSB8028 (shared intermediate dir between the
  JUCE module targets and the plugin) → stale/mismatched objects → **crash on launch**. Clean
  rebuilds fix it. This is why every build this session used `--clean-first`.
- **"launch failed" was a stale-instance race, not a code bug.** Launching a new instance while a
  prior one still holds the audio device fails. Kill the old `Breadbin.exe` and wait ~1–2s before
  `start`. Verified the exe runs clean for 12s standalone.
- **`ctest` reports `MutationTests (Failed)`** because the test exits non-zero on the 1 surviving
  triangle-boundary mutation — this is **pre-existing and within the 20% threshold**, not a
  regression. LFO + Integration are the pass/fail signal.
- UI changes can't be verified by tests — every visual change this session was confirmed by the
  user looking at the running app before commit.
